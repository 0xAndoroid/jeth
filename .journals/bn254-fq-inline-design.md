# bn254 Fq Montgomery-mul inline for jeth — design + cost sheet

Verdict first: **marginal**. BN254's q has no limb structure (all four limbs full: 0x3c208c16d87cfd47,
0x97816a916871ca8d, 0xb85045b68181585d, 0x30644e72e131a029; ark-bn254-0.5.0/src/fields/fq.rs:4), so the
reduction product m·q costs as much as a·b. The inline floor is ~60 partial-product half-terms × 4 rows ≈ 285
rows/mul vs ≈310 rows dynamic for rustc's code → −8 %. The fused 2-term `sum_of_products` inline does better
(≈419 vs ≈520, −20 %) because rustc spills ~100 loads/stores there. Block 25905781 saving ≈ 3.2 M rows
(0.48–0.69 %, central 0.51 %); blocks 785/789 ≈ 3.6 M. Squaring: no gain (ark's square is already symmetric).

Secp256k1's inline wins only because p = 2^256 − 2^32 − 977 makes w·p 4 partial products
(jolt-inlines/secp256k1/src/sequence_builder.rs:198 `LUI p, (1<<32)+977`); the same trick is unavailable here.

## 2. Proposed inline

Crate `jolt-inlines/bn254` (copy the secp256k1 crate shape: lib.rs consts, sdk.rs guest `.insn` wrappers + host fallbacks,
host.rs `register_inlines!`, sequence_builder.rs, spec.rs `InlineReference/InlineSpec`, tests.rs). Encoding: opcode 0x0B,
funct7 = 0x08 (0x00 sha2, 0x01 keccak, 0x02 blake2, 0x03 blake3, 0x04 bigint, 0x05 secp, 0x06 grumpkin, 0x07 p256 taken),
R-type: rs1 → a (32 B, 8-aligned), rs2 → b, rd → out (may alias rs1/rs2: all loads precede all stores).

| funct3 | name | semantics (all in Montgomery form, R = 2^256, inputs < q, output canonical) |
|---|---|---|
| 0x0 | BN254_MULQ  | out = a·b·R⁻¹ mod q |
| 0x1 | reserved (SQUAREQ: no row gain, see §2.3) | |
| 0x2 | BN254_SOPQ2 | rs1 → [a0,a1] (64 B), rs2 → [b0,b1]; out = (a0·b0 + a1·b1)·R⁻¹ mod q |
| 0x3 | reserved (FP2MULQ, phase 2) | |
| 0x4/0x6 | BN254_MULR / BN254_SOPR2 | same over Fr (limbs 0x43e1f593f0000001, 0x2833e84879b97091, 0xb85045b68181585d, 0x30644e72e131a029) — cheap (constants + funct3) but jeth runs ≈4 Fr muls per ecmul; only for completeness |

Algorithm: deterministic product-scanning Montgomery (FIPS/Comba), NO advice. Column k accumulates lo(x_i·y_j) for i+j=k and
hi(x_i·y_j) for i+j=k−1 over both x·y ∈ {a·b, m·q}; for k ≤ 3, m_k = r_k·INV mod 2^64 (INV = −q⁻¹ mod 2^64 = 0x87d20782e4866389)
and the term lo(m_k·q_0) is replaced by the identity r_k + lo(m_k q_0) ≡ 0 (mod 2^64) ⇒ carry = (r_k ≠ 0) = `sltu t, x0, r_k`
(saves 4 MUL + 8 rows vs `mac_discard`). Columns 4..7 are t = (a·b + m·q)/2^256 < 2q < 2^255 (so column 7 has no carry-out).
Accumulator = secp's 2-register ping-pong (`r[k%2]`, `r[(k+1)%2]`, sequence_builder.rs:225-229).
Row rule per half-term (jolt_inlines_sdk::host::MulAccExt, sdk/src/host.rs:423-520): first in column `mul/mulhu; add; sltu` = 3,
others `mul/mulhu; add; sltu; add` = 4, final column `mul/mulhu; add` = 2.

MULQ column table (L(k) = #{i+j=k} = 1,2,3,4,3,2,1):
| k | ab lo | ab hi | mq lo (j≥1) | mq hi | terms | rows |
|---|---|---|---|---|---|---|
| 0 | 1 | 0 | 0 | 0 | 1 | 3 (`mul r0,a0,b0; mul m0,r0,inv; sltu r1,x0,r0`) |
| 1 | 2 | 1 | 1 | 1 | 5 | 5·4−1 +1 (m1) +2 (zero-check carry) = 22 |
| 2 | 3 | 2 | 2 | 2 | 9 | 35 + 3 = 38 |
| 3 | 4 | 3 | 3 | 3 | 13 | 51 + 3 = 54 |
| 4 | 3 | 4 | 3 | 4 | 14 | 55 |
| 5 | 2 | 3 | 2 | 3 | 10 | 39 |
| 6 | 1 | 2 | 1 | 2 | 6 | 23 |
| 7 | 0 | 1 | 0 | 1 | 2 | 4 |
| Σ | 16 | 16 | 12 | 16 | 60 | **238** (multiplies: 16 MUL+16 MULHU ab, 12 MUL+16 MULHU mq, 4 MUL m_k = 64) |
Fixed: 8 LD + 5 LUI (q0..q3, INV; `emit_u(LUI, rd, imm: u64)` takes a full 64-bit immediate in inline context,
crates/jolt-program/src/expand/inline.rs:243, used so by secp at sequence_builder.rs:194,198) + 4 SD = 17.
Branch-free conditional subtraction c = t − q·[t ≥ q]: borrow chain `sub/sltu` (limb0 2, limbs1-3 5 each) = 17;
`addi mask, b3, -1` 1; select `xor/and/xor` ×4 = 12 → 30.  **MULQ = 238 + 17 + 30 = 285 rows** (≈310 → −25, −8 %).

SOPQ2 (terms: ab 32 + a'b' 32 + mq 28 = 92): k0 7, k1 34, k2 58, k3 82, k4 83, k5 59, k6 35, k7 6 → 364;
+ 16 LD + 5 LUI + 4 SD + 30 = 55 → **419 rows** (≈520 → −101, −20 %). Valid: t < (2q² + 2^256 q)/2^256 < 2q since 2q < 2^256
(same bound ark relies on via chunk_size = 3, sum_of_products.rs:42).
SQUAREQ: doubled cross half-terms cost 7 rows instead of 2×4 (secp `m2ac_*_w_carry`), saving 12 → ≈273 vs ≈270 compiled → skip.

Registers: MULQ 19 (a4 b4 q4 inv m4 r2 aux t → m_k can reuse a slots progressively, ≤19), SOPQ2 27; budget is 80 inline registers
(`NUM_INLINE_REGISTERS = 96 − 16`, crates/jolt-program/src/expand/allocator.rs:5-13). Virtual ops available (1 row each, tracer/src/instruction/):
VirtualAdvice, VirtualAssertEQ/LTE/ValidDiv0/…, VirtualMULI (mul by imm; would only replace the 4 q-limb LUIs), VirtualMOVSIGN,
VirtualNegateIf, VirtualPow2*, VirtualROTRI*, VirtualXORROT*, VirtualShift*, VirtualExtract*, VirtualZero/SignExtendWord. None is a
carry-flag or double-width add; no cheaper carry handling exists than add+sltu+add. A Karatsuba layer (9 vs 16 products) saves 56
rows but costs ≈70 in 128/256-bit adds/corrections and breaks column order for m_k → rejected.
Door (not this design): `field-inline` extension = native BN254 **Fr** ops in 1 row (FIELD_INLINE_MUL, jolt-sdk/src/lib.rs:27-45,
tracer/src/instruction/field_inline.rs; feature-gated, separate prover path). It is Fr not Fq; an Fq check via CRT (Fr × 2^256) still
needs the low 4 columns (~130 rows) → ~150 rows/mul, only if that prover path ever ships for jeth.

Per-op saving (rows): Fq mul −25; sop2 −101; ecmul ≈ 970·25 + 97·101 ≈ **34 k** (of ≈572 k Fq-mul rows in an ecmul, −6 %);
pairing k=1 ≈ 1512·25 + 10234·101 ≈ **1.07 M** (of ≈5.8 M, −18 %); marginal pair ≈ 0.37 M; ecadd ≈ 0.5 k.
Block 25905781: 17.6 k·25 + 27.4 k·101 ≈ **3.2 M rows = 0.51 %** (static-count worst case 4.35 M = 0.69 %; if dynamic is 305/515: 3.0 M = 0.48 %).
Blocks 25905785/789 (21 ecmul): +13·34 k ≈ +0.44 M → ≈ **3.6 M** (≈0.58 % at equal block size; scale by their actual ark share).
Phase 2, fused FP2MULQ (both sop2 of an Fp2 mul, q−b1 negation inside, shared 32 LD + 5 LUI): ≈ +60 rows per Fp2 mul over two
SOPQ2 (ark glue = `neg_in_place` + `Self::new` copies, quadratic_extension.rs:652-658, attributed to callers) → +0.8 M (781), total ≈ 0.64 %.

## 4. Soundness / correctness

- Sequence is deterministic (no VirtualAdvice/Assert rows): each row is an ordinary proven instruction, so the proof states exactly what
  the sequence computed; the only risk is the sequence ≠ REDC. Invariants used: INV·q0 ≡ −1 (mod 2^64) (zero-check trick), column carry
  counters ≤ 21 terms ≪ 2^64, t < 2q < 2^255 (single subtraction, no column-7 carry) — the last requires a,b < q (ark's invariant, same
  assumption as ark's no-carry CIOS; violating it gives a wrong-but-faithfully-proven value, not a soundness hole).
- Output canonical (< q) by construction → ark's `PartialEq`/`is_zero`/`subtract_modulus` invariants preserved.
- Tests: (1) `InlineSpec` (jolt_inlines_sdk::spec, `assert_random_cases_match_reference::<Bn254MulQ>(seed, 10_000)` +
  `assert_edge_cases_match_reference`) with `InlineMemoryLayout::two_inputs(32,32,32)` / `(64,64,32)` for SOPQ2; reference = ark
  `Fq` product on `Fq::new_unchecked(BigInt(limbs))`; edge cases {0, 1, R=Fq::ONE, R², q−1, q−1 squared, limb-boundary values
  (u64::MAX low limbs), pairs forcing t ≥ q, a == b, aliased rd == rs1}. (2) structural test like secp `test_modulus_limb_assumptions`
  (tests.rs:583): q limbs, INV, `2q < 2^256`, `INV.wrapping_mul(q0) == u64::MAX`. (3) golden row_count fixture (285 / 419).
  (4) jeth native gate: `crates/core/src/bn254.rs` `glv_mul_matches_revm_double_and_add` (10 k random + edge scalars, native → exercises
  upstream ark, unchanged); guest parity = harness test (1) + `jeth trace` of block 25905781 must reproduce the same post-state root
  (any Fq error flips ecmul/pairing outputs → validation fails). (5) jolt-eval/tracer example run with the new inline linked.
