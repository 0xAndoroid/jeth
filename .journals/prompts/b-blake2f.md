# Lane B-blake2f: a custom Jolt inline family for BLAKE2F with arbitrary round counts and 128-bit counters
LANE_WT=/Volumes/Dev/worktrees/jeth/inlines-b-blake2f · LANE_BRANCH=inlines-b-blake2f · LANE_TARGET=jeth-inlines-b-blake2f · FUNCT7=0x02 (+0x03 if needed) (opcode 0x2B)
You are a Jolt/jeth engineer. Phase A routes BLAKE2F (0x09) to the stock Jolt BLAKE2 inline only for rounds == 12 && t[1] == 0 (1067 rows); every other call runs revm's software compress at ≈ 253 rows/round, so the adversarial bound is unchanged: BLAKE2F/r1000 = 232 c/g, a 60M-gas block of it = 13.9B rows (10× the worst real block). Build an inline family that covers ALL round counts and 128-bit counters: the guest does the init (v = h ‖ IV, v12 ^= t0, v13 ^= t1, v14 = !v14 iff f) and the final fold (h[i] ^= v[i] ^ v[i+8]) in software (cheap, 16 words), and the rounds run in inlines that load v[16] + m[16] from memory, apply k rounds with the BLAKE2b sigma schedule starting at sigma index 0, and store v[16] back. Because rounds = 10·q + r with the sigma index cycling mod 10, two shapes suffice: FULL10 (rounds 0..9, one full sigma cycle) called q times, and PREFIX_r (rounds 0..r−1) for r in 1..=9 — 10 ops; funct3 has 8 values so use two funct7 blocks (0x02: FULL10 + PREFIX_1..7; 0x03: PREFIX_8, PREFIX_9) or a better encoding you justify. Per-round compute is ≈ 80–90 rows (8 G functions × (add, add, xorrot32, add, xorrot24, add, add, xorrot16, add, xorrot63) with VirtualXORROT-style fused ops where the stock BLAKE2 sequence_builder uses them — read jolt-inlines/blake2/src/sequence_builder.rs and reuse its G-function emission); load/store overhead 32 LD + 16 SD per inline call. Target: FULL10 ≈ 900–950 rows (≈ 90–95 rows/round vs 253 software), so r1000 → ≈ 90–100 rows/round, adversarial bound 13.9B → ≈ 5.5B.
Routing (crates/core/src/crypto.rs blake2_compress): rounds == 12 && t[1] == 0 → keep the stock 12-round inline; rounds == 0 → init + fold only (no inline; still must equal software); everything else → software init, q × FULL10, PREFIX_r if r > 0, fold. Decide with numbers whether 12-round calls should also move to FULL10 + PREFIX_2 (compare rows) — keep whichever is lower.
Soundness: deterministic (no advice); prove in the journal that FULL10/PREFIX_r on state (v, m) equals r rounds of revm's algo::compress round loop starting at sigma row 0 (sigma table = revm SIGMA[i % 10], IV identical), and that the software init/fold around them reproduces compress(rounds, h, m, t, f) for every rounds ≥ 0 and every t (both words). Tests: InlineSpec random 10k + edges for each op (all-zero, all-ones, m with u64::MAX words, rounds boundary), golden row counts, and a jeth-level differential test vs revm compress over random (rounds ∈ {0..=13, 19, 20, 21, 100, 1000}, t0/t1 ∈ {0, 1, max, random}, f ∈ {0,1}) plus the EIP-152 vectors.
Gates: synth configs BLAKE2F/r0, r1, r12, r13, r1000 (add r10, r20, r100) before/after; ten blocks (no BLAKE2F calls: rows unchanged, hashes + perms exact); forged blocks (EIP-152 vectors 3–8 incl. the bad-flag failure, rounds 0/1/9/10/11/12/13/100/1000, t1 ≠ 0, counter max, all-0xff h/m) guest hash == native hash.
